### Gotchas hit (recorded so future iterations don't repeat them)
1. **SDK methods take FLAT params**, not {path,query,body}. Wrong shape => the SDK silently uses undefined values => 404 / 0 messages with no obvious error. Look at sdk.gen.ts (each method signature lists allowed keys).
2. **Real SSE event shape differs from OpenAPI**:
   - `message.updated` properties = `{sessionID, info}` — info-only (no parts)
   - `message.part.updated` properties = `{sessionID, part, time}` — full part state
   - `message.part.delta` properties = `{sessionID, messageID, partID, field, delta}`
   Robust strategy: refetch session.messages on any message.* event with 150ms debounce.
3. **kiloclaw composer requires bot status to look online**. MessageArea reads `status().status === "running"` + `botStatus().online` + heartbeat freshness. Stub status() and emit periodic botStatus heartbeats every 10s.
4. **Vite alias does not work for resolveId hooks** on a per-importer basis — needed a custom plugin keyed on the importer path containing '/kiloclaw/'.

### Gotchas hit
5. **Event name is `permission.asked`**, NOT `permission.requested`. The OpenAPI spec doesn't list it; verified empirically by intercepting SSE traffic.
6. **Reply API takes `response: "once"|"always"|"reject"`**, not "allow"/"deny". Map kiloclaw's "allow-once|allow-always|deny" → "once|always|reject".
7. **Server refetch races synthesized bubbles**. `scheduleReload` from message.* events will wipe client-only ActionsBlocks unless we (a) cancel the pending reload at permission.asked time and (b) re-append pending bubbles in loadMessagesFor.
8. **newapi tenant scope matters**. The user's key only authorized GLM 5.1; Claude/GPT/DeepSeek all 403'd. GLM 5.1 *does* call tools when prompted explicitly with "use the X tool to..." patterns.
